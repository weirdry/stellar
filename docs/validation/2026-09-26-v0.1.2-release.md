## Isolated installation acceptance

Three fresh Linux arm64 containers independently installed the candidate SHA,
promoted default branch and public tag using official `skills@1.7.0`, selecting
Codex and Claude Code. Each used Node 24.21.0, npm 11.19.0 and Git 2.39.5 from
`node:24-bookworm` at digest
`sha256:6dac556d980b7f0e5498d08f08cee0ca67798b4ad6c23964a9214920e67758d0`.

```sh
npx --yes skills@1.7.0 add https://github.com/weirdry/stellar/tree/3dbdf133d8bd2c900176147b96fa9677dd961f6a --skill stellar --agent codex claude-code -g -y
npx --yes skills@1.7.0 add weirdry/stellar --skill stellar --agent codex claude-code -g -y
npx --yes skills@1.7.0 add https://github.com/weirdry/stellar/tree/v0.1.2 --skill stellar --agent codex claude-code -g -y
```

The public-tag installation passed before publishing the GitHub Release. The
canonical copy and Claude Code symlink were verified for each installation.
The installer identified Codex as a universal target and Claude Code as a symlink
target; `skills list -g` confirmed the canonical path. All **258 installed files**
matched the intended Git-tracked file set and bytes. No `.git` or `node_modules`
was installed.

Actual installed regular-file contents total **11,378,936 bytes**. `du -sk`
reported **11,844 KiB allocated** per canonical directory in the tested
filesystem. These measurements apply to the tag and default branch at the release
source, before this documentation record. They do not measure network traffic

## Limits

This is official installation plus synthetic command replay, not fresh Codex or
Claude Code invocation, automatic skill discovery or live collection. It does
not establish macOS/Windows installer acceptance, Firefox/Safari support or a new
manual visual review. Artifact comparisons do not approve classification meaning.
The current [CLI guide](../../references/cli.md) defines what doctor verifies;
its success alone does not prove source integrity or runtime acceptance.

Existing maintainer skill installations, reports, saved state and source systems
were not read or modified for these installation checks. Optional broader
TypeScript coverage hardening and product work tracked separately are not
prerequisites for this release and are not claimed complete here.
